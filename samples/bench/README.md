# Horse provider benchmark suite

Compares HTTP (and now **HTTPS/TLS**) throughput and latency across every Horse
transport provider, plus raw-transport baselines, using a shared route set so the
only variable is the provider.

> **How do I run a given bench/test?** The step-by-step command for every benchmark
> and integration test is in [`scripts/BENCH-RUNBOOK.md`](../../scripts/BENCH-RUNBOOK.md).

## Layout

```
samples/bench/
├── Common/Horse.BenchRoutes.pas     shared routes + port constants
├── Servers/
│   ├── Indy/HorseBenchIndy.dpr
│   ├── CrossSocket/HorseBenchCrossSocket.dpr
│   ├── Mormot/HorseBenchMormot.dpr
│   ├── ICS/HorseBenchICS.dpr        ← OverbyteICS provider (new)
│   ├── Raw*/…                       raw-transport baselines (no Horse)
│   │                                  RawCrossSocket / RawMormot / RawIndy / RawICS
│   │                                  (RawICS = pure ICS THttpServer, new)
│   └── Lazarus/…                    FPC/Lazarus variants
├── Client/
│   ├── HorseBenchClient.dpr         plain-HTTP comparison driver
│   └── HorseBenchTLSClient.dpr      HTTPS / mutual-TLS driver (new)
└── certs/                           self-signed TLS fixtures (gen-certs.sh)
```

## Ports

| Provider | Bare | +middleware | TLS (`--tls`/`--mtls`) |
|---|---|---|---|
| Indy | 9001 | 9011 | — |
| CrossSocket | 9002 | 9012 | **9032** |
| mORMot | 9003 | 9013 | **9033** |
| ICS | 9009 | 9019 | **9039** |
| Raw-CrossSocket / Raw-mORMot / Raw-Indy / **Raw-ICS** | 9004 / 9005 / 9006 / **9010** | — | — |

TLS port = bare + `BENCH_PORT_TLS_OFFSET` (30). Chosen to avoid the integration-test
TLS ports (9101 / 9111 / 9201).

## Server switches

All Horse bench servers share the switch parser:

| Switch | Effect |
|---|---|
| `--middleware` | RequestGuard + SecurityHeaders (also `--guard-only`, `--headers-only`, `--cors`) |
| `--async` *(mORMot)* | host `THttpAsyncServer` |
| `--httpapi` *(mORMot, Windows)* | host http.sys `THttpApiServer` |
| **`--tls`** | listen HTTPS on the TLS port using `certs/server.crt`+`key` |
| **`--mtls`** | as `--tls`, plus require + verify a client cert against `certs/ca.crt` |

## Running

### Plain HTTP
Start the provider servers (bare and/or `--middleware`), then run
`HorseBenchClient` — it sweeps all providers × scenarios and prints a Markdown table.

### TLS / mutual TLS
Use the scripts (they start the three TLS providers, run the TLS client, and clean up):

```bat
scripts\bench-tls.bat            REM one-way HTTPS bench
scripts\bench-tls.bat --mtls     REM mutual-TLS bench
```
```bash
scripts/bench-tls.sh             # Delphi-Linux64 builds
scripts/bench-tls.sh --mtls
```

Or manually:

```
HorseBenchCrossSocket.exe --tls          (→ :9032)
HorseBenchMormot.exe      --tls          (→ :9033)
HorseBenchICS.exe         --tls          (→ :9039)
HorseBenchTLSClient.exe                  (add --mtls to match --mtls servers)
```

`HorseBenchTLSClient` reports RPS + p50/p99 per provider; exit code = total errors.

## Certificates (`certs/`)

Self-signed throwaway fixtures shared with the integration tests, generated by
`certs/gen-certs.sh` (OpenSSL) and committed so no OpenSSL is needed on the build box:
`ca`, `server` (SAN `localhost`/`127.0.0.1`/`::1`), `client` (for mTLS). The bench
servers/client locate them via a `certs/` folder next to the binary (the scripts copy
this folder for you).

> **CrossSocket mutual TLS** additionally needs the two `Net.CrossSslSocket.*` mTLS
> patches (or the fork release) — see the provider README. One-way `--tls` works on
> stock upstream. mORMot/ICS mTLS work out of the box.
